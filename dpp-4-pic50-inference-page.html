Predict a batch

Upload a CSV on the live app and every row is featurised and predicted the same way.

The file needs one column headed exactly smiles (lowercase — an uppercase SMILES header raises a KeyError):

smiles
<SMILES for compound 1>

<SMILES for compound 3>

Output is a results table with predicted pIC50 and predicted IC50 (nM) per row, downloadable as CSV from the live app.

Same featurisation as Kaggle, every time

When you submit a SMILES, the features are extracted on the server at that moment — you never see or supply them yourself.

1
SMILES → molecule

RDKit parses the string into a molecular structure.

2
Morgan fingerprint

1,024 bits, radius 2 — the circular fingerprint.

3
6 physicochemical

MolWt, MolLogP, TPSA, NumHDonors, NumHAcceptors, NumRotatableBonds — in that order.

4
Named DataFrame

1,030 columns labelled feature_0 … feature_1029, as the Pipeline expects.

5
Predict

ExtraTrees returns pIC50; IC50 (nM) = 10(9 − pIC50).

Backend — invoking the model

This is the whole trick: name the repo, load the pickle, featurise, predict. Nothing else is hosted anywhere.

from huggingface_hub import hf_hub_download
import pickle

repo = "Delower/dpp4-pic50-extra-trees"
path = hf_hub_download(repo, "model.pkl")
model = pickle.load(open(path, "rb"))

# features: Morgan 1024 (radius 2) + 6 physchem, in order
# MolWt, MolLogP, TPSA, NumHDonors, NumHAcceptors, NumRotatableBonds
# -> DataFrame with columns feature_0 ... feature_1029

predicted_pIC50  = model.predict(features)[0]
predicted_IC50_nM = 10 ** (9 - predicted_pIC50)

Running it needs the packages in requirements.txt — gradio, huggingface_hub, scikit-learn, rdkit, lazypredict (needed to unpickle this model), pandas, numpy, matplotlib. On a Hugging Face Space they install automatically at startup; GitHub itself only stores the code and installs nothing. Transformers / torch are not needed for ExtraTrees — they’re only for the later Transformer, ChemBERTa, GAT and LTN models.
